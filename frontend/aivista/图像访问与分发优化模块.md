# AiVista 前端图像访问与分发优化模块

> 对应迭代：前端迭代 9——图像访问与分发优化
> 当前状态：实施中
> 维护规则：本文记录 CDN 图像 URL 的前端消费、缓存、刷新与失败处理；代码、测试、接口契约或交互规则变化时必须同步修改。

> 阶段说明：项目尚未正式部署时，前端只需保持图片 URL 不透明、支持过期刷新并避免持久化签名 URL；无需提前绑定真实 CDN 域名。CDN 切换和真实缓存/故障验收依赖最终部署环境，作为上线前任务完成，当前不阻塞其他业务迭代。

## 1. 目标与范围

阶段 1 已将同一图片的传输与消费按用途拆分为缩略图、展示图和原图；后续只将这些不透明 URL 的签发域名从 OSS 切换为 CDN，不改变页面行为、权限或前端状态模型。

## 2. 已确认约束

- 前端只消费图片 DTO 的 `imageUrls.thumbnail`、`imageUrls.display` 与各自到期时间，不拼接 CDN 路径、鉴权参数或 OSS 对象键；原图地址不出现在普通 DTO 中。
- URL、签名、图片 DTO 和提示词仅保存在运行时内存，不写入页面 URL、持久化存储、埋点或错误监控。
- 公开和资产列表只使用 `thumbnail`；打开单图详情直接复用 `display`，下载时才向作者专属接口申请 3 分钟原图 URL，复制使用 `display`。实际读取失败时最多刷新该单图一次。
- 撤销发布后，公开入口不再返回新 URL；作者仍可在个人资产入口查看同一图片。
- CDN 图片 URL 有效期初始为 10 分钟，CDN 边缘缓存为 7 天；浏览器缓存继续以 URL 有效期为上限。
- CDN 只允许实际生产前端域名及两个本地开发 Origin 的无凭证跨域读取，供前端下载和复制使用。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| URL 消费 | 前端保持域名无关，只消费后端返回的缩略图和展示图 URL。 | CDN 切换不应扩散为前端存储或签名逻辑。 | 统一领域模型为 `imageUrls.thumbnail/display`；原图仅下载接口按需签发。 |
| 缓存与刷新 | 列表复用其缩略图和展示图；打开详情不重新请求；读取失败只刷新该图一次。 | 避免为瀑布流卡片签发原图 URL，同时保证详情可立即展示。 | 不新增 CDN 专用轮询器。 |
| 撤销后行为 | 公开详情按当前后端结果处理；作者资产不受公开状态改变影响。 | 公开权限与所有权权限不同。 | 维持现有 404/不可读提示和资产详情行为。 |
| 下载与复制 | 统一通过 `fetch → Blob → Object URL` 读取 CDN 图片。 | 跨域 `<a download>` 的下载行为在浏览器间不一致；复制也必须读取 Blob。 | CDN 配置精确 Origin CORS；读取失败时按单图刷新一次后重试。 |

## 5. 页面、路由与交互设计

待实施。现有页面、路由和图片组件不因 CDN 域名变化新增页面或入口。

## 6. API、前端模型与状态管理

图片模型使用 `imageUrls`：所有普通响应均包含 `thumbnail` 与 `display`，不包含原图。禁止为 CDN 新增前端密钥、签名算法或持久化缓存；仅 URL 过期或图片读取失败时，通过既有单图详情接口取得当前 URL。下载先调用受登录和作者归属校验的接口取得临时原图 URL；复制以无凭证 `fetch` 读取 `display`。

## 7. 组件与实现位置

- `src/entities/generation/model/generation.ts`：统一 DTO、`imageUrls` 与 URL 到期判断。
- `src/features/inspiration/ui/public-inspiration-card.tsx`：仅懒加载 `thumbnail`。
- `src/entities/generation/ui/image-detail-shell.tsx`：展示与复制读取 `display`，下载按需申请原图 URL。
- `src/features/assets/ui/assets-workspace.tsx`、发布区、作者主页与通知卡片：列表仅渲染 `thumbnail`，点击详情优先复用当前 DTO 的 `display`。

## 8. 异常场景、可靠性与安全

- URL 过期、CDN 403 或浏览器跨域读取失败时，最多刷新一次单图 DTO 后重试。
- 刷新仍失败时显示既有图片不可用提示，不展示 CDN、OSS、签名或对象键细节。
- CDN 鉴权 URL 不进入浏览器持久化缓存；页面继续使用 `Referrer-Policy: no-referrer`。
