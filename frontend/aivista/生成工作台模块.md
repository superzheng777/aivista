# AiVista 生成工作台模块

> 对应迭代：前端迭代 2——生成工作台
> 当前状态：实施中
> 维护规则：本文记录普通图像生成的页面交互、任务状态和接口消费；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

接入已完成的普通文生图与图生图后端闭环，使已登录用户能创建或选择会话、提交任务、实时查看状态并管理成功图片。

当前不包含局部重绘和 Agent 模式；生成结果继续复用已实现的资产删除、收藏、发布和详情能力。

后端业务事实与接口契约以 [图像生成任务模块.md](../../backend/aivista/图像生成任务模块.md) 为准。

## 2. 已确认约束

- 接入普通文生图与最多 3 张参考图的图生图；`imageCount` 为 `1`～`6`，服务端是最终校验方。
- 进入页面加载会话列表。首次使用展示不在列表中的空白创作框；首次成功提交不传 `sessionId`，以后端 `202 Accepted` 返回的 `sessionId` 建立当前会话。
- 空白创作框成功提交前不允许再开启新的空白会话；同一会话有未完成任务时禁用再次提交。
- 每次用户主动提交生成新的 UUID v4 幂等键；重复点击、超时和网络重试复用原键。
- 用户最多四个未完成任务，每日最多请求 12 张；前端负责提示，后端负责最终限制。
- 同一会话只归类连续创作记录，不自动拼接或继承历史提示词；每次普通生成只使用本轮输入。
- 注册、登录或会话恢复时统一确认用户协议与第三方数据处理规则；生成页面不再单独弹出同意流程。
- 结果只展示成功转存图片；失败不展示虚构图片占位。普通图像生成不提供取消状态或取消操作。

## 5. 页面、路由与交互设计

路由为 `/generate`，仅认证用户可访问。URL 只接受可选的 `sessionId`，不使用 `taskId`：创作轮次接口已经包含关联任务快照。页面左侧始终展示会话列表；无 `sessionId` 时右侧为新绘画状态，居中展示生成输入区；选择历史会话或创建任务成功并获得 `sessionId` 后，右侧切换为会话工作区，上方滚动展示历史内容，下方固定生成输入区。移动端须保证会话切换、提交和结果查看可达。

每个 `GenerationTurn` 对应一个 `CreationTask`，包含真实的 USER/ASSISTANT 消息和一个普通生成任务快照。用户正向提示词和可选负向提示词显示为输入气泡；AI 回复区显示排队、处理、模型重试、失败、终态数量和生成图片。

| 场景 | 前端行为 |
| --- | --- |
| 登录/恢复 | 登录后建立并维持 SSE；收到 ready 后进入 READY。进入生成页时读取会话列表，URL 带 `sessionId` 时读取该会话的创作轮次；SSE 首连或重连完成后刷新这些页面快照。 |
| 创建任务 | 校验输入；全局用户协议确认完成且 SSE READY 后才发送 POST；`202` 后使会话列表缓存失效并跳转至携带 `sessionId` 的会话页，由页面读取会话列表和创作轮次，显示已创建的排队任务。 |
| 活动任务 | 首次 `QUEUED` 显示排队；`RUNNING` 显示“正在生成图片”；`TRANSFERRING` 显示“图片已生成，正在保存”且图片列表为空；重试的 `QUEUED/RUNNING` 显示模型重试 `n/3`。 |
| 终态任务 | 成功、部分成功、失败分别显示后端数量和安全错误提示；只显示成功图片。 |
| 无数据/网络错误 | 提供明确空状态、重试和重新连接；不清空已有内存结果。 |

## 6. API、前端模型与状态管理

| 目的 | 接口 | 前端约定 |
| --- | --- | --- |
| 用户协议 | `GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` | 由全局认证流程展示；生成页面只消费其已确认状态。 |
| 创建任务 | `POST /api/generation-tasks` | 必带 `Idempotency-Key`；`202` 后仅以返回的 `sessionId` 跳转，并刷新该会话创作轮次。 |
| 任务详情 | `GET /api/generation-tasks/{taskId}` | 任务详情保留为单任务权威快照接口，但不参与全局 SSE 对账。 |
| 会话与创作轮次 | `GET /api/generation-sessions`、`GET /api/generation-sessions/{sessionId}/turns`、`PATCH /api/generation-sessions/{sessionId}` | 会话侧栏不返回图片；接口按创作轮次游标每页最多 5 项加载，每项包含 `mode`、USER/ASSISTANT 消息及生成快照。 |
| 实时信号 | `GET /api/events` | Header 带 Bearer Token，不将 Token 放入 URL；开发环境由 `src/app/api/events/route.ts` 流式转发，生产环境由 Nginx 直接代理到 Spring Boot。 |

每个浏览器标签页最多维护一条认证用户级 SSE；多个会话和最多四个并行任务复用同一条连接，不随生成页或会话切换而重复建立。连接建立或断开后会持续自动重试：首次约等待 500ms，之后约 1s、2s，最大间隔为 3s；手动重试会重置计数。创建任务仍以 SSE READY 为门禁，等待上限为 10 秒，超时则不发送 POST。进入生成页时读取会话列表；当前 URL 带 `sessionId` 时读取对应创作轮次。每次 SSE 首连或重连完成后，生成页重新请求会话列表及当前会话轮次；不在生成页时不发送生成 REST 请求。收到任务事件时先按 `taskVersion` 更新已加载会话轮次中的生成状态与模型重试进度，再刷新已打开的会话列表；若事件属于当前会话，则立即刷新其轮次快照以取得完整结果和图片。侧栏的 `QUEUED`/`RUNNING`/`TRANSFERRING` 加载图标直接由会话列表的 `latestTask` 状态派生。`TRANSFERRING` 是非终态，不触发完成角标或资产刷新；终态 SSE 事件在当前标签页内记录未查看提示：成功/部分成功为蓝点，失败为红点。成功或部分成功事件会使活跃资产列表失效并重新请求。同版本 REST 可补全数据，旧版本响应不得覆盖新事件。

## 8. 异常场景、可靠性与安全

- `40100` 交由全局认证拦截器刷新并重放；`40102` 按工程基础文档清理会话。
- `409` 的活动任务、幂等键或同意规则冲突必须展示可行动提示；`429` 提示稍后重试；`50000` 系统繁忙时提供稍后重试。
- 任务结果、SSE 和签名 URL不得写入持久化存储、埋点或错误监控。图片页设置 `Referrer-Policy: no-referrer`。
- 会话中的任一已使用签名 URL 临近到期或图片加载失败时回查轮次快照；终态任务图片统一使用图片 DTO，当前网格只渲染 `imageUrls.thumbnail`，点击卡片即复用 `display` 打开资产详情。悬停操作提供下载原图、复制展示图及收藏/发布/删除；原图仅在下载时按作者归属申请。已删除图片仍保留 DTO 和 `sourceIndex`，但两种 URL 均为 `null`，前端显示删除占位。
- 网络重试必须复用原幂等键；前端不得自行拼接历史提示词、传服务商参数或推断任务终态。
- SSE 初次连接与断线后均会持续自动重连，重连间隔最大为 3 秒；提交前等待 SSE READY 最多 10 秒，超时则不发送创建请求。任务一旦创建，后端执行不依赖浏览器连接，重连后通过快照恢复。
