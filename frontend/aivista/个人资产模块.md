# AiVista 个人资产模块

> 对应迭代：前端迭代 3——个人资产
> 当前状态：实施中
> 维护规则：本文记录个人生成资产的页面交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

接入已完成的个人资产后端能力，使已登录用户能浏览自己的成功生成图片、查看图片与最终提示词，并按单张或手动多选删除。

本迭代不包含收藏、发布、公开展示、点赞、关注和按全部历史一键删除。

后端业务事实与接口契约以 [个人生成历史与资产模块.md](../../backend/aivista/个人生成历史与资产模块.md) 为准。

## 2. 已确认约束

- 资产最小单位是单张成功图片；资产列表只显示当前用户且未删除的图片。
- 列表按成功保存时间和图片 ID 倒序，前端使用 `Asia/Shanghai` 按日期分组。
- 资产列表全量请求，不使用游标分页，也不显示或推测总数。当前产品规模接受一次性返回全部图片和签发 URL 的成本；资产量明显增长后再评估分页或虚拟滚动。
- 列表和单图 DTO 一律提供卡片缩略图与展示图；资产页点击图片时若展示图未过期，直接复用现有 DTO，不额外请求单图详情。
- 私有签名 URL 仅在内存中使用；列表使用 `imageUrls.thumbnail`，详情展示使用 `display`，复制读取 `display`。下载原图时才调用作者专属下载接口签发 3 分钟 `original` URL；读取失败时按 `imageId` 刷新单图 DTO 一次。
- 删除使用统一批量接口；只提交用户手动勾选的 `imageIds`，重复删除按成功处理。
- 删除成功即从资产页移除；OSS 后台清理不阻塞前端，也不能恢复可见性。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 详情数据来源 | 卡片保留列表项作为即时上下文；资产页与官方消息入口均按 `imageId` 请求资产详情。 | 列表不签发展示图和原图，避免全量列表携带无用 URL。 | 两入口统一使用同一详情 DTO 和组件；详情关闭后不单独缓存资源。 |
| 桌面端详情布局 | 保持首页侧边栏；右侧主体切换为左右双栏，左栏居中展示图片，右栏展示提示词与操作。 | 详情仍属于资产浏览上下文，不离开当前页面；图片周边留白可作为直观关闭区域。 | 不新增详情路由或全屏遮罩；左栏空白区域点击关闭详情，右栏承载关闭、删除等操作且不触发关闭。 |
| 批量操作入口 | 资产页右上角提供“批量操作”按钮；进入后才显示图片复选框、已选数量和“取消选择”。 | 默认点击图片保持预览语义，避免与删除混淆。 | 管理模式中可对手动勾选的图片执行删除或下载。 |
| 批量操作范围 | 本迭代实现删除与下载；迭代 4 已加入图片表持久化收藏及批量收藏。发布只支持单张资产详情，不支持批量发布。 | 收藏属于图片创建者，使用明确目标状态的批量接口；发布是单张图片的审核提交。 | 删除和收藏均复用批量接口；下载仅使用内存中的短期签名 URL，过期或 OSS 读取失败时按单图刷新一次后重试；迭代 4 移除批量发布占位。 |
| 批量下载 | 多选下载逐张触发浏览器下载，不生成 ZIP 包。 | 不新增压缩文件生成服务，也避免后端暂存私有资产。 | 用户选择多张图片后依次触发下载；浏览器拦截时提示用户允许多文件下载。 |
| 图片复制 | 复制图片二进制到系统剪贴板；失败时提示用户下载图片。 | 详情操作栏需要直接复用当前图片，不引入链接复制语义。 | 浏览器从 OSS 短期签名 URL 读取 Blob 后写入 Clipboard API；OSS 需允许前端站点 Origin 的 `GET` 跨域请求，无需按用户 IP 配置或新增 Nginx 代理。 |
| 详情右栏信息结构 | 顶栏操作、提示词、生成参数三段纵向排列；右栏整体可滚动，顶栏吸顶。 | 操作随时可达，提示词保持阅读空间，参数不与创作内容混杂。 | 顶栏提供关闭、下载、复制图片和迭代 4 的收藏；作品操作区提供迭代 4 的发布；删除独占危险操作行。 |
| 生成参数数据 | 展示比例、尺寸、生成时间、本次生成数量和提示词优化开关。 | 为用户保留可追溯的创作配置。 | 统一图片 DTO 的 `generationConfig` 包含 `width`、`height`、`requestedImageCount` 和 `promptExtend`；`createdAt` 用于生成时间。 |
| 资产网格 | 仅适配桌面端窗口宽度，采用 `repeat(auto-fill, minmax(220px, 1fr))` 的自适应列数。 | 宽屏充分利用空间，窄桌面窗口仍保持可识别的卡片尺寸；不扩展到移动浏览器布局。 | 图片使用统一圆角缩略图；悬停显示轻遮罩与生成时间，管理模式才显示复选框。 |
| 删除确认 | 单图与批量删除使用同一确认弹窗。 | 统一不可撤销操作的风险提示。 | 文案为“将永久删除 N 张图片，此操作无法撤销”，操作为“取消 / 删除 N 张图片”。 |
| 日期分组 | 前端按北京时间分组，后端按 UTC 的 `created_at DESC, id DESC` 返回全量结果。 | 保持用户展示习惯与稳定顺序。 | 首次加载后直接完成日期分组。 |
| 删除交互 | 单图与多选复用确认和同一接口。 | 删除语义一致，减少重复链路。 | 成功后从本地列表乐观移除；失败则恢复并提示。 |
| 已删除快照 | 资产页不展示已删除图片。 | 当前页仅展示可管理资产。 | 任务/会话中的无 URL 占位由生成工作台模块处理。 |

## 5. 页面、路由与交互设计

路由为 `/assets`，仅认证用户可访问。页面应包含日期分组的图片网格、全量加载状态、空状态、错误重试、图片详情视图和删除操作。桌面端打开详情后，保留左侧固定导航；右侧主体分为左右两栏，左栏在留白画布中居中展示图片，点击图片周边留白关闭详情。右栏宽度建议固定在 `360px`～`400px`，包含吸顶操作栏、提示词区和生成参数区；右栏内的操作不得触发关闭详情。

| 场景 | 前端行为 |
| --- | --- |
| 首次加载 | 请求全部资产；空列表显示“尚无生成图片”及前往生成入口。 |
| 查看详情 | 优先复用列表的 `display` 大图；仅 URL 过期或图片读取失败时请求单图详情一次。 |
| 详情操作栏 | 提供关闭、下载、复制图片和收藏；发布位于作品操作区；删除使用独占危险操作行。 |
| 详情参数 | 展示比例、尺寸、生成时间和本次生成数量。 |
| URL 到期 | 不继续使用失效 URL，只刷新当前单图详情，不重拉资产列表。 |
| 生成完成 | 资产页处于活动状态时，收到全局 SSE 的成功或部分成功任务事件后，使列表缓存失效并重新请求；新图加载完成后确认本标签页的新结果提示。 |
| 批量操作 | 点击右上角“批量操作”进入管理模式；顶部显示“已选 N 张”和“取消选择”，卡片显示复选框。 |
| 删除单图/多选 | 明确永久删除确认，提交用户选中的 ID；成功后从网格移除。 |
| 下载单图/多选 | 使用当前内存中的签名 URL 下载所选原图；URL 已过期时按单图刷新，OSS 读取失败时仅刷新并重试一次。 |
| 图片复制 | 读取当前签名 URL 的图片并写入系统剪贴板；URL 已过期或 OSS 读取失败时按单图刷新一次，浏览器权限或 CORS 仍失败时提示用户下载图片。 |
| 收藏/发布 | 迭代 4 后，收藏支持单图和批量的当前页内存切换；发布仅在单张详情中提交审核，不支持批量发布。 |
| 删除失败 | 保留原项与选择状态，显示安全错误消息并允许重试。 |

本迭代仅实现桌面端 Web；移动浏览器适配与后续单独规划的 React Native App 均不在当前范围。删除按钮不得与图片预览点击区域混淆。具体视觉和组件取舍待实现前确认。

## 6. API、前端模型与状态管理

| 目的 | 接口 | 前端约定 |
| --- | --- | --- |
| 全量资产列表 | `GET /api/generation-images` | 直接消费全量图片数组；响应按 UTC 的 `createdAt DESC, imageId DESC` 排序，前端完成北京时间分组。 |
| 单图资产详情 | `GET /api/generation-images/{imageId}` | 供官方消息“查看作品”按需读取；成功 DTO 与资产列表单项相同，`404` 显示“该图片已删除”。 |
| 删除图片 | `POST /api/generation-images/delete` | 请求为 `{"imageIds":["101","102"]}`；成功 `data` 为 `null`。 |

领域模型保留 `imageId`、`imageUrls.thumbnail/display`、`width`、`height`、`createdAt`、`finalPrompt`、`finalNegativePrompt`。原图 URL 不属于图片 DTO；不得将 URL 存入本地持久化缓存；删除请求不按资源存在性展示差异，以符合后端归属隔离语义。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 统一遵循工程基础文档的认证处理。
- 全量资产请求失败时保留当前已展示快照并提供重试；不使用游标或 `limit` 参数。
- 删除接口的“已删除、他人或不存在均成功”是安全约束，UI 不得试图区分资源存在性。
- 签名 URL、提示词和图片不得写入持久化存储、URL、埋点或错误监控；详情页面使用 `Referrer-Policy: no-referrer`。
