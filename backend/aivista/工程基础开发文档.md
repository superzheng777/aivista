# AiVista 工程基础开发文档

> 文档类型：工程基础
> 对应迭代：迭代 0——工程基础
> 当前状态：已完成
> 维护规则：本文记录项目运行、测试、通用配置、部署与联调约定。工程基础变化时，代码、测试和文档必须同步修改。

## 1. 项目入口与常用命令

项目为 Spring Boot 后端，默认地址为 `http://localhost:8888`，所有业务接口统一使用 `/api` 前缀。

```powershell
# 当前可用：运行测试
mvn test

# 当前可用：启动应用
mvn spring-boot:run
```

`mvnw.cmd` 是项目 Maven Wrapper。请在 `backend/aivista` 目录优先使用 `.\mvnw.cmd test` 和 `.\mvnw.cmd spring-boot:run`，以统一团队使用的 Maven 版本。Wrapper 已验证可运行；首次使用会按其配置下载 Maven 发行版和缺失依赖。

## 2. 已有基础能力

| 能力 | 使用方式 / 约定 |
| --- | --- |
| 健康检查 | `GET /api/health`；用于本地启动后确认服务可用。 |
| 接口文档 | Knife4j：`/api/doc.html`；Swagger UI：`/api/swagger-ui.html`；OpenAPI JSON：`/api/v3/api-docs`。新增 Controller 接口时应补充 OpenAPI 注解。 |
| 统一响应 | Controller 成功响应使用 `ResponseUtils.success(data)`，结构固定为 `code`、`message`、`data`。 |
| 业务异常 | 可预期的业务失败使用 `BusinessException` 和 `ErrorCode` 抛出，由全局异常处理器统一转换为 HTTP 响应。 |
| 参数校验 | 请求 DTO 使用 Jakarta Validation 注解；校验失败由全局异常处理器统一返回。 |
| 请求代理 | 生产环境由同一公开域名下的 Nginx 直接代理 `/api`；开发环境由 Next.js 代理，普通 REST 使用 rewrite，SSE 使用专用 Route Handler。浏览器始终通过页面同源地址访问后端。 |
| 跨域 | 仅在无法使用开发代理时直接跨域访问后端；允许来源在配置文件的 `app.cors.allowed-origins` 中维护。本地 Next.js 默认允许 `http://localhost:3000` 与 `http://127.0.0.1:3000`。携带认证 Cookie 时必须使用明确来源并显式允许凭证，不得使用通配来源。新增浏览器自定义请求头（如生成任务的 `Idempotency-Key`）时，只有在直接跨域调用后端的部署方式下，才必须同步加入后端 CORS 的允许请求头；通过同源 `/api` 代理访问时不触发浏览器 CORS 预检。 |
| 日志 | 未处理异常由全局异常处理器记录；业务代码应使用 SLF4J 记录必要上下文，避免记录密码、令牌等敏感信息。 |

## 3. 代码位置

| 位置 | 职责 |
| --- | --- |
| 各业务模块的 `api` 包 | HTTP 接口层，例如 `auth/api`、`user/api`、`health/api`。 |
| `common/response` | 统一响应对象与创建工具。 |
| `common/exception` | 错误码、业务异常和全局异常处理。 |
| `common/request` | 通用请求 DTO 基类。 |
| `config` | 跨域和 OpenAPI 等工程配置。 |
| `application.yaml` | 可提交的基础配置与 `AIVISTA_*`、`MEILISEARCH_*` 环境变量占位符；不得填写数据库、RabbitMQ、Meilisearch、百炼或 OSS 的真实凭证。 |
| `application-local.example.yaml` | 可提交的本地配置模板；仅保留占位符。 |
| `application-local.yaml` | Git 忽略的本地 `local` Profile 覆盖文件；本机真实连接信息和密钥仅写入此文件。 |

## 4. 开发约定

- 每次开发同步修改代码和相关文档。
- 新模块开始前，先补充该模块的详细设计文档；数据库表、API、权限和测试规则在该文档中确定。
- 新增接口遵循统一响应和异常处理约定，不在 Controller 中自行拼装错误响应。
- 迭代状态变化时，同步更新《后端项目开发文档》。
- 本地需要访问 MySQL、RabbitMQ、Meilisearch、百炼或 OSS 时，先复制 `application-local.example.yaml` 为 `application-local.yaml`，填写本机真实值，并通过 `SPRING_PROFILES_ACTIVE=local` 启动；不得将该文件提交到仓库。

## 5. 部署与联调约定

当前仍处于功能开发和本地/服务器联调阶段。生产交付配置、基础可观测性、告警和备份恢复属于一期上线前的必要工作，统一纳入迭代 11；它们不阻塞当前业务功能开发，但正式上线前必须完成并经过演练。应避免为了尚未确定的生产拓扑过早固化容器编排、监控平台或灾备实现。

- 生产环境规划由 Nginx 将同一域名下的 `/api` 请求直接代理至 Spring Boot 服务，客户端不直接访问后端内部地址；`/api/events` 必须关闭缓冲、缓存和压缩，保留认证 Header，配置长读取超时。当前开发阶段不提供或启用生产 Nginx 配置，正式部署时另行实现并验证。
- 开发环境由 Next.js 将普通 `/api` 请求 rewrite 至 `http://localhost:8888`；`/api/events` 由专用 Route Handler 流式转发。两条代理链路都保留原始 `/api` 路径、Cookie 和必要的认证头。
- `/api/events` 是认证用户按浏览器标签页维持的一条用户级 SSE 流，复用命名事件承载生成状态、官方消息及后续互动等轻量通知。领域状态必须先持久化，随后经 Outbox 推送事件；断线重连后的 REST 快照才是权威对账来源。服务端发送心跳，客户端在网络恢复或页面重新可见后重连。
- Spring Boot 应只信任受控代理写入的转发头；生产环境的 HTTPS、真实客户端地址和协议由 Nginx 统一传递。
- 若部署方式改为前后端跨站，必须重新评估 CORS、Cookie `SameSite`/`Secure` 属性及 CSRF 防护，不得直接沿用当前认证配置。

### 5.1 当前联调与迁移拓扑

- 当前开发期允许前端、Spring Boot 和 MySQL 继续运行在本地，而 RabbitMQ 先部署在服务器。后端通过服务器的 RabbitMQ 地址连接队列；前端和 MySQL 不因该部署方式而需要迁移。
- Meilisearch 也部署在该服务器。本地 Spring Boot 经服务器公网 `7700` 联调时，安全组和主机防火墙只能放行当前开发机公网 IP；正式部署时改为后端与 Meilisearch 的私有网络连接。
- 开发期服务器安全组及主机防火墙仅临时允许开发者固定公网 IP 访问 RabbitMQ AMQP 端口 `5672`。管理端口 `15672` 同样仅限固定 IP，或通过 SSH 隧道访问；不得向全网开放这两个端口。
- RabbitMQ 必须创建独立业务账号并使用强密码，不使用默认 `guest/guest` 账号；消息数据和配置必须使用持久化存储，容器重建后不得丢失。
- 后续前后端及后端服务迁移到同一服务器后，RabbitMQ 应仅供后端通过 `localhost:5672` 或受限容器内部网络访问，并关闭公网 `5672` 与 `15672` 入站规则。届时由 Nginx 仅对外暴露 HTTP/HTTPS（`80`/`443`）。

### 5.2 当前服务器约定

- 当前服务器用于 RabbitMQ 与 Meilisearch 联调，租用周期暂定 1 个月。前端、Spring Boot、MySQL、Nginx 和 Redis 当前均不部署到服务器。
- 当前实例使用杭州地域 Ubuntu 24.04 LTS、`2 vCPU / 1 GiB RAM / 30 GiB` 磁盘；该规格只保证当前低负载 RabbitMQ 联调。准备迁移 Spring Boot 或其他应用前，应升级至至少 `2 vCPU / 4 GiB RAM`。
- RabbitMQ 使用 Docker Engine 与 Docker Compose Plugin 部署；容器数据和配置必须通过 Docker Volume 或宿主机持久化目录保存。当前管理员在服务器上执行 Docker 命令时使用 `sudo docker`，不将普通用户加入 Docker 用户组。
- 本地私网地址（例如 `192.168.x.x`）不可作为安全组来源。每个可信网络出口均以独立 `公网 IPv4/32` 规则放行；不得为图省事扩大为无关网段。
- 当前仅保留可信来源访问 SSH `22`。`80`、`443`、ICMP、RabbitMQ `5672` 和管理端口 `15672` 在实际需要前保持关闭；其中 `5672`、`15672` 启用后也只能对白名单公网 IP 或 SSH 隧道开放。
- Vercel 可用于前端预览、个人演示和分支部署，不作为首版生产任务链路。正式首版仍由服务器的 Nginx、Spring Boot 与 RabbitMQ 承担；Vercel 不运行 RabbitMQ 消费者或核心生成任务。

### 5.3 当前 RabbitMQ 部署记录

- 生成模块使用显式 Durable Direct Exchange `aivista.generation.commands`。Java 通过 Outbox 发布 `generation.task.execute` 与 `generation.image.transfer` 持久化命令，TS 分别使用 25 和 15 个 `prefetch=1` 的手动 ACK 消费通道执行百炼与 OSS I/O；TS 将版本化结果发布到 `generation.worker.result`，由 Java 幂等消费并完成任务、额度、资产和状态事务。旧 Java Worker 和运行切换开关已经删除。
- Outbox 发布同时启用 correlated Publisher Confirm、Mandatory 和 Publisher Return；只有交换机确认且消息未因无绑定被退回时，事件才标记为已发布。

- 服务器已通过 Docker 官方 APT 仓库安装 Docker Engine 与 Docker Compose Plugin；Docker 守护进程可运行容器。部署目录固定为 `/opt/aivista/rabbitmq`。
- Docker Hub 直连在当前服务器网络中会超时，因此已配置阿里云 ACR 账号专属镜像加速器。该加速器无法解析 RabbitMQ 的 `4.3.4-management` 与 `4.1.8-management` 固定标签，表现为 `not found`；这是镜像加速器同步范围的限制，不是 Docker 或 Compose 配置错误。
- 当前加速器可拉取通用标签 `rabbitmq:management`，实际获得 RabbitMQ `3.9.11`。为避免通用标签在未来产生隐式版本变化，当前镜像应在本机重新标记为 `aivista/rabbitmq:3.9.11-dev`，Compose 使用该本地标签并设置 `pull_policy: never`。
- RabbitMQ `3.9.11` 仅作为当前 1 个月开发联调的临时运行时；其支持 Quorum Queue，但版本已过旧，不得用于后续正式部署。正式环境必须使用受支持的 RabbitMQ 4 固定版本，并使用可验证的镜像供应方案。
- 当前 Compose 配置必须使用独立业务用户 `aivista`、私有虚拟主机 `/aivista`、`restart: unless-stopped`、`rabbitmq_data` Docker Volume，以及 `5672` / `15672` 端口映射。账号密码仅保存在权限受限的 `/opt/aivista/rabbitmq/.env`，不得写入 Compose 文件、代码仓库、截图或聊天记录；一旦泄露必须立即重新生成并替换。
- RabbitMQ 容器已于当前开发服务器成功通过 `sudo docker compose up -d` 启动；Docker 网络 `rabbitmq_default`、持久化卷 `rabbitmq_rabbitmq_data` 和容器 `aivista-rabbitmq` 均已创建，容器状态为 `Up`，启动日志包含 Quorum Queue 组件初始化。容器健康检查、业务用户登录和本地到 `5672` 的 TCP 连通性均已验证。
- 已删除默认 `guest` 用户，仅保留 `aivista` 业务用户。安全组已使用抓包确认的实际 TCP 出口 IP 配置 `22`、`5672`、`15672` 单地址白名单；本地 IP 查询服务返回值不作为该白名单依据。当前管理后台 `15672` 保留可信公网 IP 直连，后续也可切换为 SSH 隧道并关闭其公网规则。
- 当前 RabbitMQ 运行环境与 Java Outbox、TS 手动 ACK Worker、Java 结果消费者的跨服务链路集成已完成，并通过真实百炼、RabbitMQ 和 OSS 端到端验收。图片流式转存与 OSS 服务端派生图已完成真实联调：原图、卡片 WebP 与展示 WebP 均成功生成。`80`、`443`、ICMP 不属于当前联调范围，应保持关闭，待网站部署时再按需开放。
- 本地 Spring Boot 联调时，`spring.rabbitmq.host` 填开发服务器公网 IP 或域名、`port` 填 `5672`、`virtual-host` 固定为 `/aivista`；用户名和密码分别填写服务器 `/opt/aivista/rabbitmq/.env` 中 `RABBITMQ_DEFAULT_USER`、`RABBITMQ_DEFAULT_PASS` 的实际值。`aivista-rabbitmq` 是服务器 Docker 容器名，不是本地后端可使用的远程主机名；`15672` 只用于人工管理后台，不作为应用连接端口。

### 5.4 当前 Meilisearch 部署记录

- 部署目录固定为 `/opt/aivista/meilisearch`，使用 Docker Compose、独立持久化卷和 `restart: unless-stopped`。当前运行 Meilisearch 1.53.1；不使用 `latest` 作为 Compose 配置的镜像版本。
- Master Key 仅保存于该目录权限受限的 `.env`，只用于创建受限 API Key；Spring Boot 本地配置仅使用 Search、Admin、Task 三把受限 Key，三者均不得写入仓库或前端。
- `7700` 当前仅为本地后端联调向开发机公网 IP 放行；健康检查使用容器内 `http://127.0.0.1:7700/health`。服务迁移后关闭公网入站，并经私有网络连接。
