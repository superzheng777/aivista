# AiVista 图像访问与分发优化模块

> 对应迭代：迭代 9——图像访问与分发优化
> 当前状态：实施中
> 维护规则：本文记录私有 OSS 图像的 CDN 分发、访问鉴权、缓存与撤销边界；代码、配置、测试和文档必须同步修改。

> 阶段说明：项目尚未正式部署时可以先完成对象模型、URL 抽象和缓存/失效规则，不需要提前启用真实 CDN。域名、证书、私有回源、鉴权密钥和真实缓存验收依赖最终部署环境，作为上线前任务完成；当前未接入 CDN 不阻塞其他业务迭代。

## 1. 目标与范围

在不公开 OSS Bucket、不改变图片对象归属的前提下，先将每张图片固化为适合不同读取用途的三个对象；后续再将读取链路从 OSS 短期签名 URL 升级为 CDN 时效签名 URL，并使用 CDN 回源私有 OSS Bucket。

本迭代覆盖公开作品、作者私有资产、详情、下载和复制所使用的图片 URL；不新增公开 Bucket、公开副本、客户端 OSS 凭证或图片代理服务。阶段 1 已落地对象组和按用途签发，尚未接入 CDN。

## 2. 已确认约束

- OSS Bucket 保持私有，CDN 使用受限身份回源；CDN 私有回源本身不等同于用户访问鉴权。
- 每张生成图片的 `generation_images.object_key` 保存对象组前缀而不是文件键：`{prefix}/original.png` 为原图，`{prefix}/card.webp` 为列表卡片（长边 640、质量 80），`{prefix}/display.webp` 为详情展示（长边 1600、质量 85）。原图流式写入后由 OSS 服务端 `ProcessObject + sys/saveas` 持久化两种派生图，应用不解码像素。
- 统一图片 DTO 固定为 `imageUrls.thumbnail/display`，列表卡片使用 `thumbnail`、详情复用 `display`；原图不属于普通 DTO，只能由认证作者通过专属下载接口按需签发。删除仍清理三个对象，任务快照也复用双 URL DTO。
- CDN 产品选用阿里云 CDN，不使用 ESA；本迭代只使用静态图片分发、私有 OSS Bucket 回源和 URL 鉴权能力。
- 后端在完成当前业务权限校验后签发 CDN URL：公开接口仅对当前已发布作品签发；作者资产接口仅对图片所有者签发。
- 撤销发布后，公开接口不再签发新 URL；作者本人仍可通过资产接口为同一 OSS 对象取得新 URL。
- 已签发 URL 在其时效内仍可访问，初始沿用 10 分钟有效期；这与当前 OSS 短期签名 URL 语义一致。
- URL、签名、CDN 密钥、OSS 对象键和访问凭证不得写入数据库、日志、埋点、错误监控或客户端持久化存储。
- 图片对象内容不可变时，CDN 边缘缓存初始设置为 7 天；浏览器私有缓存仍以 URL 时效为上限。若未来要求撤销后立即使已签发 URL 失效，需要独立的边缘撤销能力，不以 CDN 缓存刷新替代。
- CDN 鉴权使用主 Key 与备 Key，后端只使用当前活动 Key 签发 URL；首版由管理员手动轮换，切换窗口内主备 Key 同时有效。
- CDN 图片响应只向实际生产前端域名及 `http://localhost:3000`、`http://127.0.0.1:3000` 返回 CORS 允许来源；不使用通配符，不允许 Cookie 凭证。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 分发架构 | CDN 时效签名与 CDN 私有 OSS Bucket 回源组合使用。 | 前者控制用户访问，后者保护 CDN 到 OSS 的回源；二者不是替代关系。 | 后端签发 CDN URL；OSS 不再直接向浏览器签发公开作品读取 URL。 |
| CDN 产品 | 使用阿里云 CDN。 | 当前只需要静态图片分发，避免引入 ESA 的边缘计算与全站安全治理复杂度。 | 按阿里云 CDN 的私有回源、URL 鉴权、缓存和响应头能力实施。 |
| 鉴权密钥轮换 | 使用 CDN 主/备 Key 手动平滑轮换。 | 当前密钥数量和发布频率低，无需引入自动化密钥编排。 | 先将新 Key 配为备 Key，部署后端改用新 Key，等待超过 10 分钟后提升为主 Key 并移除旧 Key。 |
| CDN 跨域响应 | 仅允许已知前端 Origin 的无凭证 `GET`/`HEAD` 跨域读取。 | 下载与复制需要前端读取 Blob；CORS 不是图片访问鉴权。 | CDN 开启跨域验证，精确匹配 Origin；URL 鉴权仍独立执行。 |
| 对象复用 | 公开作品和作者资产复用同一私有 OSS 对象。 | 避免复制、双写与删除一致性问题。 | 按调用接口及当前权限决定是否签发 URL。 |
| 撤销语义 | 撤销后停止公开签发，已签发 URL 自然过期。 | 与现有 URL 时效语义一致，首版不引入边缘状态存储。 | 公开详情和列表继续按当前发布状态校验。 |
| CDN 访问方式 | 优先使用可在边缘校验并排除鉴权参数缓存干扰的 URL 鉴权方式。 | 不同用户的短期 URL 可复用边缘缓存，同时保持时效控制。 | 具体 CDN 鉴权类型与参数格式在实施前确认。 |
| 对象派生与消费 | 保存原图、卡片 WebP、展示 WebP 三个私有对象；列表、详情、下载分别使用对应资源。 | 不依赖 CDN 实时处理也能显著降低列表与详情下行流量，且不增加应用内存中的像素解码。 | `object_key` 语义改为对象组前缀；普通 DTO 一律签发缩略图与展示图，原图只由作者下载接口按需签发。 |

## 5. 设计与实现

已实施阶段 1：TS `GenerationImageTransferService` 写入 `{prefix}/original.png` 后让 OSS 生成两个派生对象，再由 Java 结果消费者原子创建资产；`GenerationImageObjectKeys` 集中定义 Java 侧对象键；`GenerationAssetQueryService`、`GenerationTaskQueryService` 和 `InspirationQueryService` 为普通图片 DTO 签发 `thumbnail`、`display`；`GenerationAssetQueryService.originalDownload` 只在当前用户是作者时签发 3 分钟 `original.png` URL；`GenerationAssetOssCleanupService` 删除整个对象组。任务快照也复用同一双 URL DTO。

待实施阶段 2：把上述签发器由 OSS 预签名切换为 CDN 时效签名；DTO 字段和调用方不感知 URL 域名的变化。

## 6. 数据模型与配置

不新增业务表，也不持久化 CDN URL 或签名。CDN 边缘缓存 TTL 为 7 天，签名有效期初始沿用 10 分钟。待确认配置包括 CDN 域名、活动鉴权密钥注入方式、回源身份和证书配置。CDN 控制台同时保存主 Key 与备 Key；后端仅注入当前活动 Key。

## 7. API 与权限

图片 DTO 的资源字段为 `imageUrls.thumbnail/display`，每个非空值包含 URL 与到期时间。公开读取必须先验证发布状态；私有读取必须先验证当前用户是图片所有者。原图下载另走认证作者专属接口，签发 3 分钟 URL；CDN 只验证已由后端签发的短期 URL，不承担业务身份判断。

## 8. 异常场景、可靠性与安全

- CDN 鉴权失败或 URL 超时按图片读取失败处理，前端按既有单图刷新规则重新请求详情 DTO。
- CDN 或回源不可用不得泄露 OSS 域名、对象键、签名或密钥。
- OSS 保持私有；禁止用 Referer 防盗链或 CDN 缓存刷新替代 URL 鉴权与撤销策略。
- CDN 对允许 Origin 返回 `Access-Control-Allow-Origin` 与 `Access-Control-Allow-Methods: GET, HEAD`，不返回 `Access-Control-Allow-Credentials`；鉴权失败在浏览器中可能表现为 403 或跨域读取失败，均按单图读取失败处理。
- 未来若引入立即撤销，必须评估边缘鉴权状态、成本、可用性与作者私有访问的兼容性。
