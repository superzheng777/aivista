# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：后端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：已完成
> 维护规则：本文是迭代 4 后端实现的当前依据；代码、测试、接口或数据结构变化时必须同步更新。

## 1. 已实现范围与边界

一张 `image_assets` 记录代表用户私有图片资产，`image_publications` 保存其发布状态和公开文案；不创建公开 Bucket 或公开图片副本。原图始终位于私有 OSS Bucket。

- 发布仅审核用户本次提交的标题和描述；不审核图片和生成提示词。图片与提示词的安全边界由生成链路负责。
- 审核通过后写入 `public_at`；匿名灵感接口只为已发布图片签发 10 分钟私有 URL。
- 资产删除与撤销发布独立：资产软删除不清空 `public_at`，即使资产已删除仍可撤销发布；只有两者都不可见时才安排 OSS 清理。
- 发布失败原因不写入图片表。用户可见的结果由官方消息展示；技术错误仅保留在 Outbox 的 `last_error`，不对用户暴露。
- 社区互动上线后，撤销发布会清除该图片全部点赞；重新发布进入新的公开周期，点赞从 0 开始。
- 标题、描述分别调用文本审核。拒绝消息只保存安全的字段名和原因码，不保存供应商原始标签、命中词、命中位置或置信度。
- 收藏仅属于图片创建者，因此使用图片表的布尔字段 `is_favorited`，不创建独立收藏关联表。

## 2. 发布状态与重试

`image_publications.public_at IS NOT NULL` 是图片当前已公开的唯一事实。`review_status` 是发布流程状态，取值如下：

| 状态 | 含义 | 能否再次提交 |
| --- | --- | --- |
| `NONE` | 从未提交、撤销发布后的初始状态 | 可以 |
| `PENDING` | 等待或正在进行文本审核 | 可重复提交；直接返回现有的 `202 PENDING`，不创建第二个审核任务 |
| `APPROVED` | 审核通过，`public_at` 非空 | 不可以，需先撤销 |
| `REJECTED` | 标题或描述审核未通过，`public_at` 为空 | 可以 |
| `FAILED` | 审核服务连续三次异常后终止，`public_at` 为空 | 可以 |

状态流转：

```text
NONE / REJECTED / FAILED --提交--> PENDING --审核通过--> APPROVED
                                      |--中/高风险--> REJECTED
                                      |--连续三次异常--> FAILED
PENDING --删除发布--> NONE
APPROVED --撤销--> NONE
```

- 每次调用审核服务前递增 `review_attempt_count`。
- 审核服务异常按 30 秒间隔重试，最多 3 次；中、高风险不是技术异常，不重试。工作器领取审核后若 2 分钟未完成，会释放过期领取并按同一上限恢复；不会永久停留在 `PENDING`。
- `none`、`low` 风险等级直接通过；`medium`、`high` 不公开。
- 标题和描述保留在图片记录中，便于用户再次提交；它们在 `public_at` 为空时不会出现在公开查询中。
- `publication_version` 用于隔离撤销或重新提交后迟到的审核结果。旧版本结果条件更新失败时直接丢弃。

## 3. 数据模型

V16 将图片资产和发布状态规范化为 `image_assets` 与 `image_publications`；收藏字段位于资产表：

| 字段 | 当前用途 |
| --- | --- |
| `public_at` | 非空表示当前公开。 |
| `review_status` | 发布流程状态。 |
| `publication_version` | 发布流程乐观版本。 |
| `review_attempt_count` | 当前提交的审核调用次数。 |
| `review_started_at` | 本次提交开始审核的时间，也是个人发布列表的统一排序时间。审核通过后保留，拒绝、失败或删除发布后清空。 |
| `title` / `description` | 审核输入及通过后的公开文案。 |
| `is_favorited` | 当前图片创建者的收藏状态，默认 `false`。 |

V7 同时创建：

- `user_notifications`：通用用户消息。迭代 4 的官方消息记录接收用户、图片 ID、类型、标题、内容和可选 `metadata_json`；迭代 5 追加互动消息所需的点赞者与公开周期字段，具体契约以《社区身份与互动模块》为准。拒绝消息的元数据形如 `{"violations":[{"field":"title","reasonCode":"CONTENT_POLICY"}]}`，可同时包含标题和描述两项。
- 通用 `outbox_events`：文本审核任务和 SSE 状态事件均通过它可靠投递。
- 通用 `idempotency_records`：用于生成任务创建的幂等响应；发布审核不使用防重表，而是以图片发布状态实现业务幂等。

## 4. 当前接口

| 功能 | 方法与路径 | 当前行为 |
| --- | --- | --- |
| 提交发布审核 | `POST /api/generation-images/{imageId}/publication` | 仅图片所有者可调用；请求体为 `title`（1–100）和 `description`（1–500）；可提交状态下创建审核并返回 `202 Accepted` 和 `PENDING`。若图片已是 `PENDING`，直接返回 `202 PENDING`，不重复写入审核 Outbox；若已发布，要求先撤销发布。不推送 `PENDING` SSE；用户进入发布页后由列表请求获取该状态。 |
| 删除发布 | `DELETE /api/generation-images/{imageId}/publication` | 对 `PENDING` 取消审核，对 `APPROVED` 撤销发布；两种情况均保留资产原图，并将状态重置为 `NONE`。不推送状态事件；当前标签页直接从内存列表移除，其他标签页由用户手动刷新。 |
| 批量设置收藏 | `POST /api/generation-images/favorites` | 仅所有者可调用，请求体 `{ imageIds: string[], favorite: boolean }`。写入目标状态而非切换，重复收藏或取消收藏均成功且幂等；任一图片不存在、非本人或已删除时返回 `40401`，整批不更新。 |
| 公开作品列表 | `GET /api/inspirations` | 无需登录；只返回 `public_at` 非空且 `APPROVED` 的图片、公开文案、生成提示词和短期私有 URL。分页与详情规则见《灵感社区模块》和《发现能力模块》。 |
| 我的发布 | `GET /api/users/me/publications` | 返回当前用户全部 `PENDING` 与 `APPROVED` 图片，按提交审核时间和 ID 倒序，不分页。资产已软删除的公开图片仍会返回。 |
| SSE | `GET /api/events` | 复用认证用户级 SSE 连接。仅在审核终态推送 `publication.updated`，数据为 `imageId`、`publicationVersion`、`status` 与 `publicAt`。 |
| 官方消息列表 | `GET /api/users/me/official-notifications?cursor={cursor}` | 按 `(created_at DESC, id DESC)` 固定每页 15 条游标分页，返回 `{ items, nextCursor }`；不接受客户端 `limit`。拒绝消息的 `metadata.violations` 可同时指出标题、描述问题。 |
| 消息中心未读数 | `GET /api/users/me/notifications/unread-count` | 返回 `officialUnreadCount`、`interactionUnreadCount` 与 `totalUnreadCount`；迭代 4 的官方消息角标与迭代 5 的互动页签共用此快照。 |
| 标记官方消息已读 | `POST /api/users/me/official-notifications/{notificationId}/read` | 仅当前用户自己的官方消息可操作；重复调用保持成功，其他用户或已删除消息返回 `404`。 |
| 全部标记已读 | `POST /api/users/me/official-notifications/read-all` | 将当前用户全部未删除的官方消息标记为已读；无未读消息时也成功。 |
| 删除单条官方消息 | `DELETE /api/users/me/official-notifications/{notificationId}` | 仅软删除当前用户自己的官方消息；其他用户或已删除消息返回 `404`。 |
| 批量删除官方消息 | `POST /api/users/me/official-notifications/deletions` | 请求体为 `{ notificationIds: string[] }`，软删除当前用户指定的未删除消息；不存在、非本人或已删除 ID 按已满足目标状态处理，重复调用成功。 |

## 5. 可靠事件与官方消息

发布提交由 Java 在一个本地事务内写入 `image_publications` 的 `PENDING` 状态和 `PUBLICATION_TEXT_REVIEW` Outbox 事件。Java 的发布审核调度器以条件更新领取事件，在不持有数据库事务的情况下调用阿里云内容安全，再由发布版本条件更新幂等提交审核结果。进程中断后通过处理租约恢复，技术异常有限重试；发布状态、审核调用、通知和失败恢复均由发布领域单一所有。

审核终态由 `PublicationReviewOutcomeService` 在同一个本地事务中完成三件事：

1. 条件更新图片的发布状态及 `public_at`；
2. 写入一条 `user_notifications` 官方消息；
3. 写入 `PUBLICATION_STATUS_CHANGED` Outbox 事件。

其中 `eventType` 表示发生的是“发布状态变化”，`aggregateType = GENERATION_IMAGE` 表示该事件归属的实体是生成图片，`aggregateId` 为图片 ID。由于不存在独立的发布表，这不是“生成事件”和“发布事件”冲突。

SSE 分发器消费 `PUBLICATION_STATUS_CHANGED` 并向当前在线用户发送 `publication.updated`。事件包含 `imageId`、`publicationVersion`、`status` 和 `publicAt`。SSE 仅做实时提示，离线或断线不会影响数据库状态；官方消息持久化后由消息读取接口作为权威快照展示。

前端在认证期间维持一条用户级 SSE 连接。收到审核终态 `publication.updated` 后，资产和灵感页不自动更新；这些页面在重新挂载或用户刷新时请求最新快照。个人中心发布区若正在打开，则按事件中的图片 ID、版本、状态和 `publicAt` 合并内存数据，不重置列表、滚动位置或当前打开的详情。事件版本不高于内存版本时直接丢弃。`APPROVED` 项仅更新状态标签，不因审核通过改变列表位置；`REJECTED`、`FAILED` 项从发布区移除。当前标签页删除发布后直接从内存列表移除，不等待 SSE。其他标签页不做自动同步，用户手动刷新后获得最新快照。若当前详情对应的图片因终态被移除，详情保留结果提示，用户关闭后回到列表。前端自动刷新官方消息未读数，并在消息抽屉打开时刷新消息列表。SSE 不携带官方消息正文或未读数，REST 响应始终是消息数据的权威来源。SSE 重连成功且发布区正在打开时，前端在后台重新请求全量发布列表并差量合并；不得重置列表、滚动位置或当前详情。

## 6. 已实现的接口契约

以下契约已完成代码、测试与 OpenAPI 同步：

- 资产、个人发布和公开作品共用同一个图片 DTO。DTO 包含 `imageId`、`imageUrls`、`createdAt`、`favorited`、最终正负提示词、`generationConfig`、`publicationReviewStatus`、`publicationVersion`、`publicAt`、`title` 和 `description`。`imageUrls` 固定为 `thumbnail`、`display` 两个可空项：列表渲染 `thumbnail`，详情复用 `display`；`original` 不随普通 DTO 返回，只能通过作者专属下载接口按需签发。`generationConfig` 至少包含 `width`、`height`、`requestedImageCount` 与 `promptExtend`。匿名公开列表的 `favorited` 固定为 `false`，不暴露作者的私有收藏状态。
- `null` 只表示该图片在业务上没有对应值，例如未发布图片的 `publicAt`、`title`、`description` 与可选负向提示词；不得表示因权限裁剪而省略字段。
- 公开作品列表只返回 `APPROVED` 图片，因此其 `publicationReviewStatus` 恒为 `APPROVED`。资产、个人发布和公开作品详情均公开最终正负提示词和 DTO 中的生成配置；作者资料、关注关系和点赞规则见《社区身份与互动模块》与《灵感社区模块》。
- `GET /api/users/me/publications` 保持全量、不分页，返回当前用户的 `PENDING` 与 `APPROVED` 图片。两种状态混排为单一列表，`PENDING` 项显示“审核中”，`APPROVED` 项显示“已发布”；`REJECTED` 与 `FAILED` 不进入该列表，由官方消息告知结果。统一按 `review_started_at DESC, asset_id DESC` 排序，审核通过后保留该时间，`publicAt` 仅用于展示公开时间。
- `GET /api/generation-images` 改为返回当前用户全部未删除资产，不再接收 `cursor` 或 `limit`，也不返回 `nextCursor`。排序仍为 `created_at DESC, id DESC`。这是针对当前产品规模的明确取舍；资产量显著增长时再重新评估响应大小、签名 URL 签发成本和加载时间。
- 审核终态 `PUBLICATION_STATUS_CHANGED` 事件扩展为 `imageId`、`publicationVersion`、`status` 和 `publicAt`。不为提交 `PENDING` 或删除发布 `NONE` 投递 SSE；跨标签页由用户手动刷新同步。`publicationVersion` 是每次提交发布递增的单调审核版本，不设业务上限；它用于客户端丢弃过期审核终态事件和后端隔离迟到审核结果，不用于展示或作为业务计数。

## 7. 阿里云内容安全配置

当前使用阿里云内容安全增强版的 `ugc_moderation_byllm_pro` 文本审核服务，调用接口为 `TextModerationPlus`。应用暂时复用现有 OSS RAM 凭证；该凭证已增加 `AliyunYundunGreenWebFullAccess`，未在本次实现中改动或新增密钥。

标题与描述分别作为文本请求发送；供应商原始风险标签、命中词、请求内容、对象键、签名 URL 和异常栈不得写入官方消息或普通日志。当前安全原因码为 `CONTENT_POLICY` 与 `SENSITIVE_INFO`，前端按 `metadata_json.violations` 标记对应输入框。
